Recommendation

Moving prior authorization requests off fax

I mapped how prior authorization requests reach our team by fax, phone and portal, traced why some reached us with much of their deadline already used up, and recommended a phased fix with a plan for measuring it. This is a recommendation and hasn't been implemented yet.

The problem

A late-entry authorization is a request that gets created in our system after its regulatory clock has already started running. The clock starts when the request arrives, not when someone enters it. There were two main causes:

  • Fax server delays, the biggest cause. Faxed requests could sit in a backed-up server before anyone saw them.
  • Requests entered under the wrong member, so they effectively didn't exist for the right person until someone noticed.

The insight: we only found out after the fact

Nobody could see the fax backlog building. We learned the servers had backed up when workload suddenly spiked with a wave of authorizations that were already late and hard to catch up on. The real problem wasn't only the delay. It was that the delay was invisible until it became a crisis.

What I recommended

  1. Move providers from fax to the portal. Portal requests arrive as structured data in real time, with no server to back up and less room to attach a request to the wrong member. UM supervisors would start with outreach to the providers who send the most faxes.
  2. Automatically extract key fields from the faxes that remain, so they reach the review queue faster and with fewer entry errors.

The portal shift also lines up with where the industry is going: the CMS prior authorization API requirements taking effect in 2027 push plans toward electronic submission.

How I'd measure it
